## コードレビュー

- コードや文書を変更したら、`/difit` スキルを使ってユーザーにレビューを依頼すること

## ファイル書き込み

- Write ツール（Overwrite file）の事前確認はスキップすること
- レビューは `/difit` で行うため、Write 時点でのユーザー確認は不要

## 選択・確認は AskUserQuestion を使う

ユーザーへの問いが「選択肢を列挙できる」なら **必ず `AskUserQuestion` ツール**で出す。free-text のメッセージで「〜しますか？」と書いてターンを終えてはいけない。

### 必ず AskUserQuestion を使うケース

- **継続確認 / Yes・No**: 「commit & push しますか？」「これで進めて良いですか？」「OK？」「reviewer 追加しますか？」
- **投稿前の最終確認**: PR・Issue・メッセージの送信前 OK チェック
- **設計案の選定**: A 案 vs B 案、配置パスの選択、命名候補
- **次アクションの分岐**: 「(1) X やる / (2) Y やる / (3) 何もしない」

Yes/No は 2 択 `[Yes (Recommended), No]` で十分（Other は自動付与されるので明示不要）。
推奨選択肢は先頭に置き、ラベル末尾に `(Recommended)` を付ける。

### free-text で問うのは以下だけ

- 長文の文面（コミットメッセージ案、PR description 案）に対する修正指示
- エラーログ・スクリーンショット・URL の貼り付け依頼
- 数値・ファイルパス・固有名詞など、列挙不能な具体値の入力依頼

「ユーザーが自分で判断して指示する」場面でも、列挙できるなら AskUserQuestion の方がタイピングコストが小さく早い。

### Anti-patterns（やりがちな違反）

- ❌ 「〜しますか？」と平文で書いてターンを終える
- ❌ 「次どうしますか？」と選択肢を出さずに丸投げする
- ❌ 「進めて良ければ続けます」と暗黙の Yes/No 確認を free-text で混ぜる

### ターン終了前のセルフチェック

応答を出す直前に **必ず** 自問する: **「これはユーザーに何かを選ばせる問いか？」**

Yes なら、平文の質問を消して `AskUserQuestion` に置き換えてから返答する。

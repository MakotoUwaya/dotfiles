# Memory Compaction

## 概要

`~/.claude/projects/<project>/memory/` に蓄積されたメモリファイルを統合圧縮し、
セッション開始時の `MEMORY.md` 読み込み上限（先頭 200 行 / 25 KB）内に収めつつ、必要な記憶の再現性を最大化します。

## 使用タイミング

- 「メモリを圧縮して」「memory compaction」「メモリを掃除して」と指示されたとき
- `MEMORY.md` の行数やファイルサイズが肥大化してきたとき
- 過去のフィードバックや知見が散乱し、整理が必要になったとき

## 実行手順

### Step 1: メモリ状況の把握と概算トークン数の算出
1. カレントプロジェクトに対応するメモリディレクトリを特定する:
   - ディレクトリ: `~/.claude/projects/<project-slug>/memory/`
   - （例: パス区切りを `--` に、`/` や `:` を `-` に変換）
2. メモリディレクトリ内のファイル一覧・ファイル数・合計バイト数を取得する。
3. 合計バイト数を 4 で割り、概算トークン数を算出・記録する。

### Step 2: メモリの全件読み込み
- **途中で読み込みを打ち切らない**: 事実が複数の統合先に分散するのを防ぐため、必ずすべてのメモリファイルと `MEMORY.md` を読み込む。

### Step 3: グルーピングと統合
1. **分類の基準**:
   - 単なる `type`（user / feedback 等）の機械的分類ではなく、**「同じ場面で一緒に思い出したいか」**を軸にグルーピングする。
   - 統合後ファイルサイズの目安: 1 ファイルあたり **3〜7 KB**。
2. **項目の畳み込み**:
   - 1 つのトピックを以下の 4 要素（1 段落）に圧縮する:
     - **見出し語**: 何に関する知識か
     - **事実**: 確定した仕様や起きた事象
     - **理由（Why）**: なぜそうなったか、指摘された背景（※応用が利くよう、理由は絶対に削らない）
     - **適用**: 次にどう行動すべきか（コマンド、ファイルパス、設定値など）
   - かつて誤りと判明した結論がある場合は、「〜は誤り」と理由を明記して残す（同じ過ちを繰り返さないため）。
3. **削除・削減対象**:
   - frontmatter の冗長な重複
   - 完了済みの「次のステップ」や一時的な作業メモ
   - 既に `.claude/rules/` や `CLAUDE.md` に昇格済みの確定ルール

### Step 4: バックアップと置換
1. 既存メモリの退避アーカイブを作成する:
   - コピー先: `~/.claude/memories/memory-archive-<YYYYMMDD>/`
2. アーカイブの件数と元の件数が一致していることを確認した上で、旧メモリファイルを整理・更新する。

### Step 5: MEMORY.md（インデックス）の再生成
1. 各メモリファイルにつき 1 行、以下の形式で再生成する:
   ```markdown
   - [タイトル](filename.md) — フックとなる検索キーワードや適用場面
   ```
2. **フックの要件**: 単なる要約ではなく、Claude が「このファイルを開くべきか」を正確に判断できる検索キー・トリガー語句を記述する。
3. 全体で **200 行以内 / 25 KB 以内** に収まっていることを検証する。

### Step 6: 圧縮結果のレポート
ユーザーに以下の項目を端的に報告する:
- 圧縮前のファイル数・バイト数・概算トークン数
- 圧縮後のファイル数・バイト数・概算トークン数
- 削減率（%）
- 落とした情報・削除した項目（「何がどこへ行ったか」のトレーサビリティを確保するため）

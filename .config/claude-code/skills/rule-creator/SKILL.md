# Rule Creator

## 概要

Claude Code のルール（`.claude/rules/` や `CLAUDE.md`）を追加またはメンテナンスし、
ルール肥大化や重複を防ぎながら、AI が確実に先回りして指示に従える状態を維持します。

## 使用タイミング

- 「新しいルールを追加して」「ルールを作成して」と指示されたとき
- メモリ（MEMORY.md）内の確定した知見を永続的なルールに昇格させたいとき
- 「このルールを短くして」「ルールを整理・圧縮して」と指示されたとき

## 実行手順

### モード A: ルールの新規作成・昇格

#### 1. 要件確認と重複チェック
- **制御対象の明確化**: 何を制限・推奨したいのか、理由（Why）は何か。
- **重複の確認**:
  - `ls .claude/rules/` およびキーワードによる `grep` を `CLAUDE.md` と既存ルールに実行する。
  - すでに類似ルールが存在する場合は、新規作成ではなく**「既存ルールの更新・追記」**を提案する。

#### 2. スコープと paths の決定
- **常駐かオンデマンドかの判定**:
  - プロジェクト全体で常に守らせたいルール → `paths` を省く（セッション開始時に常駐）。
  - 特定の言語、ファイル種別、またはサブディレクトリにのみ関係するルール → `paths` で絞り込む。
  ```yaml
  ---
  paths:
    - "**/*.ts"
    - "src/**/*.tsx"
  ---
  ```
- **配置先のスコープ**:
  - リポジトリ固有のルール: `.claude/rules/<topic-slug>.md`
  - ユーザー個人・全体ルール: `~/.claude/rules/<topic-slug>.md`（※グローバルでは paths 付きルールが効かない場合があるため原則常駐として記述）

#### 3. ルールファイルの記述規約
- **1ファイル1トピック**: 異なるトピックを1つのファイルに混在させない。
- **検証可能な粒度**: 「適切に」「綺麗に」といった曖昧な表現を避け、具体的なコマンド、パス、インデント幅、禁止パターンを箇条書きで記述する。
- **理由（Why）の付与**: 強すぎる命令（ALWAYS / NEVER 等）に頼るのではなく、「なぜこの制約が必要なのか」を1文添えることで、AI の文脈応用力を高める。
- **行数制限**: 原則 **200行以内** に収める。

#### 4. 長大ルールの .claude/references/ への退避
ルール本文が長くなりそうな場合（図解、詳細なステップ、OK/NG対比表、検出スクリプトなど）:
1. 判断に毎回必要な制約・基準だけを `.claude/rules/<topic>.md` に残す。
2. 詳細・手順・対比表は `.claude/references/<topic>-details.md` に退避する。
3. ルール側の末尾に以下のような相対リンクを1行記述する:
   ```markdown
   詳細な手順やエラー対応表は [references/<topic>-details.md](../references/<topic>-details.md) を参照。
   ```

---

### モード B: 既存ルールの圧縮・整理

「ルールを短くして」等の依頼があった場合:

1. **削除してはいけない重要要素の保護**:
   - 検出コマンド、正規表現、正確なオプション指定
   - 例外条件やホワイトリスト
   - frontmatter（paths 設定等）
2. **圧縮のテクニック**:
   - **重複した情報源の一本化**: 表形式の一覧と検出正規表現が重複している場合、正規表現を正として表を削る。
   - 冗長な前置きや自明な説明文を削り、箇条書きに畳み込む。
3. **退避の適用**:
   - 圧縮後も長大な場合は、上記の手順に従い `.claude/references/` への詳細退避を実施する。
4. **報告**:
   - 削減行数だけでなく、「何を守り、どのように整理したか」を明示する。

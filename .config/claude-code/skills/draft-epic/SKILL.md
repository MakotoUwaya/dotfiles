# Draft Epic - GitLab Epic セクション記述支援

## Overview

GitLab Epic のテンプレートセクションを、ユーザーとの対話を通じて段階的に埋めていくスキル。
Slack の会話ログ、関連 Issue、既存の関連 Epic など複数の情報源を収集し、不明点はユーザーに質問しながら記述する。

## When to Use

- GitLab Epic の内容が TBW（To Be Written）の状態で、セクションを埋めたい時
- 「Epic の内容を詰めたい」「Epic を書いて」「Epic のドラフトを作って」と指示された時
- Epic の URL や番号が提示された時

## Instructions

### 1. 情報収集（並列実行）

以下を並列で取得する:

- **GitLab Epic**: `glab api "groups/{group}/epics/{iid}"` で現在の description を取得
- **Slack 会話**: 指定されたスレッドを `slack_read_thread` で取得
- **関連 Issue**: backlog に関連 Work Item があれば `glab api` で背景を把握
- **関連 Epic**: 同時に作成された Epic があれば取得してスコープの境界を把握

### 2. 判断が難しい点をユーザーに質問

`AskUserQuestion` を使って、以下のような判断ポイントを確認する:

- 技術的な方針（例: 実装方式の選択）
- MVP のスコープ
- ユーザーストーリーの主語と価値の方向性
- 各 Epic 間のスコープ境界

**重要**: 情報源から読み取れない判断事項は推測せず、必ずユーザーに確認する。

### 3. テンプレートセクションの記述

以下のセクション構成に従って記述する:

```markdown
## この取組みのゴール
- この Epic 単体で達成すること（関連 Epic のスコープを含めない）

## あえて含めないと決めたこと
- 意図的にスコープ外としたもの（関連 Epic への参照を含む）

## 背景
- なぜこの取組みが必要か
- ビジネス上の文脈、技術的な前提条件

## ユーザーストーリー
- 「{役割}として、{機能}がほしい。{理由}からだ」の形式
- 理由部分でこの Epic のスコープ内の価値を述べる

## 取組みの成功を決める指標
- 定量的に測定可能な指標

## この取組みで検証する最大の仮説
- この取組みの前提となる不確実な想定

## 取組みが失敗するとしたら、何が原因か
- リスク要因（技術的・運用的・ビジネス的）

## 機能要件
- 具体的な実装項目

## 検討した代替案
- テーブル形式: | 代替案 | 不採用理由 |

## 取り組みの結果レポート
- TBW（リリース後に記載）
```

### 4. Epic の更新

```bash
glab api -X PUT "groups/{group}/epics/{iid}" \
  -f description="$(cat <<'EPICEOF'
{content}
EPICEOF
)"
```

### 5. ユーザーのフィードバック反映

ユーザーからの修正指示に応じて Epic を更新する。関連 Epic のスコープにも影響する場合は、複数の Epic を並列で更新する。

## Guidelines

- **スコープ境界を厳守**: 関連 Epic（例: &290, &291）のスコープに属する内容を混ぜない
- **ユーザーストーリーの価値**: この Epic 単体で提供する価値を述べる。後続 Epic の価値を先取りしない
- **「物件ログ」ではなく「物件登録」**: 業務用語はユーザーの指示に従う
- **ベストエフォートの明示**: データ品質に課題がある場合、「ベストエフォートで登録し、ユーザーが確認・修正する運用」のように割り切りポイントを明記する
- **TBD の活用**: MTG 待ちなど未確定事項は TBD と明記し、推測で埋めない
- **関連 Epic の参照**: `&{iid}` 形式で相互参照する
